The `docs/` directory is a flat collection of Markdown design documents rather than executable code. The authoritative reference is `architecture.md` (v2.0 Final Reconciled), which cross-references the PRD, technical plan, user journeys, quality checklist, and the ADR in `architecture-decision-medusa-v2.md`. `data-models.md` is explicitly marked SUPERSEDED by the canonical `database.md` outside this scope and retained only as historical draft; its supersession notice is the key boundary signal. `dfd.md` / `dfd-review.md`, `architecture-review.md`, `database-fix-report.md`, `database-review.md`, `medusa-admin-reference-audit.md`, and `prompt-9-medusa-setup-report.md` are review/audit artifacts that resolve findings against the authoritative reference. Dependency direction is one-way: review reports cite `architecture.md` and `dfd.md`; nothing in `docs/` is imported by source code — it is the human-readable contract between product, engineering, and QA.
