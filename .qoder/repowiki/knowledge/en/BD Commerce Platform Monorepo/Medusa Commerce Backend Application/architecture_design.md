Built on Medusa v2 (`@medusajs/framework` 2.22.0), the app is a standard Medusa project whose entry point `medusa-config.ts` registers seven custom modules under `src/modules/bd-*`. Each module follows the same internal layout: an `index.ts` exporting a named `Module(...)` descriptor with a service class, a `service.ts` extending `MedusaService({ ...models })`, a `migrations/` folder with TypeORM migrations plus a `.snapshot-*.json` file, and a `models/` folder of entity classes — this pattern is uniform across bd-audit, bd-campaigns, bd-catalog, bd-courier, bd-orders, bd-payments, and bd-settings.

Cross-module relationships are declared in `src/links/` via `defineLink`, e.g. linking the core `OrderModule.linkable.order` to `BdOrdersModule.linkable.orderBdDetails`. Custom HTTP endpoints live under `src/api/admin/custom` and `src/api/store/custom` as route files, while shared middleware (e.g. search index allowlisting) is registered through `src/api/middlewares.ts` using `defineMiddlewares` + `configureStoreSearch`. The admin UI lives in `src/admin/` (Vite-based, with its own `tsconfig.json` and i18n). Additional cross-cutting code includes `src/lib/region-store-policies.ts`, `src/search/product.ts` with helpers, `src/workflows/`, `src/subscribers/`, and `src/jobs/` (all currently README stubs). Build, dev, migration, and test scripts are defined in `package.json` and driven by the Medusa CLI.
